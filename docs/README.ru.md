# Восстановление NVRAM HP 534FLR-SFP+ (BCM57810)

[English](../README.md) · [Polski](README.pl.md) · [Українська](README.uk.md) · **Русский**

Инструменты и инструкции для восстановления сетевых карт HP FlexFabric 10Gb 2-port **534FLR-SFP+** (Broadcom/QLogic **BCM57810**, `14e4:168e`, subsystem `103c:1930`), у которых во флешке SPI оказался несогласованный набор прошивки. Метод подходит и для других карт на BCM57810/bnx2x с такой же структурой NVRAM.

Состав репозитория:

| Путь | Что внутри |
|---|---|
| `firmware/esp-serprog/` | Прошивка, превращающая **ESP32 / ESP8266** в SPI-программатор для [flashrom](https://flashrom.org) (протокол `serprog`) |
| `tools/nvmtool.py` | Утилита для образов: анализ дампа, болванка без данных карты, сборка образа под конкретную карту (Python 3, без зависимостей) |
| `tools/bnx2x_nvm.py` | Доступ к NVRAM прямо из Linux через PCI BAR0 карты: лог MCP, чтение, запись (без выпаивания) |
| `templates/` | Обезличенная болванка для 534FLR-SFP+ (прошивка 7.14.62, без данных карты) |

> Болванка в `templates/` не содержит данных карты (MAC, серийный номер). Исходные дампы реальных карт здесь не хранятся: каждый содержит серийный номер и MAC-адреса конкретной карты. См. [Где взять болванку](#5-где-взять-болванку).

---

## 1. Симптомы

Карта не видна в iLO и ОС, в `dmesg`:

```
bnx2x: [bnx2x_init_shmem:...]BAD MCP validity signature
bnx2x 0000:05:00.0: part number 394D4342-31383735-31543030-47303030
bnx2x: [bnx2x_get_igu_cam_info:...]CAM configuration error
bnx2x 0000:05:00.0: probe with driver bnx2x failed with error -22
pci 0000:05:00.0: VPD access failed.  This is likely a firmware bug on this device.
```

Управляющий процессор (MCP) в BCM57810 запускает bootcode с флешки, но не завершает инициализацию. Причину показывает его собственный трассировочный буфер (`bnx2x_nvm.py trace`, раздел 3):

```
MFW1 7.16.15 Begin, TS 0x965d72 SI 0x8020458.
...
no img 0x30000003
load failure
```

В случае, с которого начался этот проект, карту сломало **прерванное обновление прошивки HPE**. Утилита *HPE QLogic NX2 Online Firmware Upgrade Utility* (CP064333, MBI 7.14.79 → 7.19.27) записала новый bootcode 7.16.15, удалила старые модули MCP и завершилась ошибкой (`Return code: 7`), не записав новые. CRC всех образов во флешке остались правильными, но bootcode не нашёл нужный ему набор модулей. `nvmtool.py info` распознаёт такую ситуацию. Решение — записать полный согласованный набор прошивки с рабочей карты, сохранив MAC-адреса и серийный номер своей карты.

> ⚠️ На том же сервере (Debian 13 / Proxmox VE, ядро 7.0 — неподдерживаемая ОС) это обновление второй раз сломало карту точно так же. После восстановления **не запускайте** там этот компонент прошивки NX2.

Если карта ещё видна на шине PCI, её можно восстановить **прямо из Linux, не выпаивая флешку** (раздел 3). Иначе чип снимают и программируют внешним программатором (раздел 4).

## 2. Флешка M45PE16

- Маркировка: **4SPE16**, ST/Micron **M45PE16**, 16 Мбит (2 МБ), корпус SO8W (208 mil), 2,7–3,6 В.
- JEDEC ID: `0x20 0x40 0x15`.

⚠️ **Распиновка M45PE16 — НЕ стандартная для 25-й серии.** Стандартные SOIC8-переходники, клипсы и панели для этого чипа подключены неправильно:

```
          ┌───────┐
    D   1 │●      │ 8  Q       D  = вход данных (MOSI)   Q   = выход данных (MISO)
    C   2 │       │ 7  VSS     C  = тактовый (SCK)       VSS = земля
 Reset  3 │       │ 6  VCC     S  = выбор чипа (CS#)     VCC = 3,3 В
    S   4 │       │ 5  W       W  = защита записи        Reset = сброс, активный 0
          └───────┘
```

Reset (пин 3) **обязательно** подтянуть к 3,3 В, иначе чип останется в сбросе и будет читаться как `0xFF`/`0x00`.

Кроме того, у семейства M45PE **нет команды полного стирания** (Bulk/Chip Erase), есть только Page Erase `0xDB` и Sector Erase `0xD8`. От этого зависит выбор программатора.

## 3. Восстановление из Linux без выпаивания

Если `lspci -nn -d 14e4:168e` показывает карту, но драйвер не поднимается, NVRAM можно читать и записывать через собственный NVRAM-интерфейс карты в PCI BAR0, той же последовательностью регистров, что и драйвер bnx2x. Для `tools/bnx2x_nvm.py` нужны только Python 3 и root. Функция не должна быть привязана к драйверу; после неудачного probe она и не привязана.

```
B=0000:05:00.0                                    # PCI-адрес функции 0

python3 tools/bnx2x_nvm.py $B trace               # состояние MCP и его лог: почему он остановился
python3 tools/bnx2x_nvm.py $B read backup1.bin    # вся NVRAM 2 МБ, около 2 с
python3 tools/bnx2x_nvm.py $B read backup2.bin
cmp backup1.bin backup2.bin
python3 tools/nvmtool.py info backup1.bin
```

Соберите образ для своей карты (раздел 6) и запишите его:

```
python3 tools/bnx2x_nvm.py $B testpage 0x180000   # проверка записи на одной странице, затем восстановление
python3 tools/bnx2x_nvm.py $B write my_card_new.bin
python3 tools/bnx2x_nvm.py $B read check.bin
sha256sum my_card_new.bin check.bin               # должны совпадать
```

- `write` перезаписывает только отличающиеся страницы по 256 байт (обычно несколько сотен, это секунды), затем читает и сверяет всю флешку.
- NVRAM-контроллер карты сам стирает каждую страницу, поэтому M45PE16 записывается, хотя TL866II+ этого не умеет.
- После записи **выключите сервер и отключите питание на 30–60 с**. MCP работает от дежурного питания и перечитывает bootcode только после полного обесточивания.
- Если запись прервётся, карта может пропасть с шины PCI; тогда используйте внешний программатор (раздел 4) и резервную копию.

## 4. Программаторы

### 4.1 TL866II+ (minipro): только чтение

TL866II+ чип **читает**, но **записать не может**. Его прошивка стирает SPI-флешки только командой Bulk Erase (`0xC7`), которую M45PE16 игнорирует. minipro всё равно пишет `Erasing... OK`, затем записывает данные поверх нестёртых, и проверка не проходит. В чипе остаётся `старое AND новое`. Профиль `M45PE16` в базе minipro задан только для T48/T56. Алгоритма для TL866II+ нет, и обновление прошивки программатора его не добавляет.

Для чтения на TL866II+ ноги чипа соединяют с теми контактами ZIF, которые занимала бы стандартная SOIC8-флешка 25-й серии (верх панели, со стороны рычага):

| Пин M45PE16 | Сигнал | Контакт ZIF | (позиция стандартной флешки) |
|---|---|---|---|
| 4 | S | 1 | CS |
| 8 | Q | 2 | DO |
| 5 | W | 3 | WP |
| 7 | VSS | 4 | GND |
| 1 | D | 37 | DI |
| 2 | C | 38 | CLK |
| 3 | Reset | 39 | HOLD (в «1») |
| 6 | VCC | 40 | VCC (3,3 В) |

```
minipro -p "M45PE16@SOIC8" -D            # ожидается: Chip ID: 0x204015  OK
minipro -p "M45PE16@SOIC8" -r dump.bin
```

### 4.2 ESP32 / ESP8266 + flashrom: чтение и запись ✅

flashrom поддерживает M45PE16 (включая посекторное стирание) и работает с ESP через USB-UART по протоколу `serprog`.

#### Сборка и прошивка ESP

Нужен [PlatformIO](https://platformio.org):

```
cd firmware/esp-serprog
pio run -e esp32   -t upload --upload-port /dev/ttyUSB0     # ESP32 DevKit
pio run -e esp8266 -t upload --upload-port /dev/ttyUSB0     # NodeMCU / Wemos D1 mini
```

Проверка, что flashrom видит программатор (флешку пока не подключать):

```
flashrom -p serprog:dev=/dev/ttyUSB0:921600
# serprog: Programmer name is "esp-serprog"
```

Предупреждение `Warning: NAK to query serial buffer size` — ожидаемое и безвредное.

#### Подключение (прямо к ногам чипа)

| Пин M45PE16 | Сигнал | ESP32 | ESP8266 (NodeMCU) |
|---|---|---|---|
| 1 | D (MOSI) | GPIO23 | D7 (GPIO13) |
| 2 | C (SCK) | GPIO18 | D5 (GPIO14) |
| 3 | Reset | **3V3** | **3V3** |
| 4 | S (CS) | GPIO5 | D1 (GPIO5) |
| 5 | W | **3V3** | **3V3** |
| 6 | VCC | **3V3** | **3V3** |
| 7 | VSS | GND | GND |
| 8 | Q (MISO) | GPIO19 | D6 (GPIO12) |

- Питание **только от 3V3**, никогда от 5V/VIN.
- Провода короткие (≤ 10–15 см). Частота SPI по умолчанию 4 МГц (максимум 8 МГц).
- Подключайте провода при отключённом USB.
- Вариант для ESP32 проверен на реальном железе с M45PE16. Вариант для ESP8266 собирается, но на железе не проверялся.

#### Чтение и запись

```
P="serprog:dev=/dev/ttyUSB0:921600"

flashrom -p $P -c M45PE16                       # поиск: Found ... "M45PE16"
flashrom -p $P -c M45PE16 -r backup1.bin        # чтение (≈30 с)
flashrom -p $P -c M45PE16 -r backup2.bin
cmp backup1.bin backup2.bin && echo "чтение стабильное"

flashrom -p $P -c M45PE16 -w new.bin            # стирание + запись + проверка (≈3 мин)
flashrom -p $P -c M45PE16 -r check.bin
sha256sum new.bin check.bin                     # должны совпадать
```

Если при поиске приходит `id1 0xff` (MISO подтянут, чип молчит), проверьте питание и Reset на пинах 6 и 3, а также проводку. Если и TL866 читает `0xff`, почти всегда виновата неправильная разводка.

## 5. Где взять болванку

Нужен полный дамп NVRAM на 2 МБ с **рабочей** карты той же модели (тот же PCI subsystem ID: `103c:1930` для 534FLR-SFP+). С рабочей карты в Linux-сервере:

```
ethtool -e <iface> raw on > working_dump.bin      # 2097152 байт
```

Либо прочитайте её флешку программатором, как описано выше.

### Готовая болванка

В репозитории есть готовая болванка `templates/534FLR-SFP+_fw7.14.62_template.bin`. Это обезличенный дамп рабочей 534FLR-SFP+ (`103c:1930`): bootcode 7.14.62 с полным согласованным набором модулей MCP (7.14.62/7.14.37), MBA 7.14.10. Все контрольные суммы верны. Данные карты заменены заглушками: MAC `02:4e:56:4d:00:00`…`07`, SN `XXXXXXXXXX`, код даты `0000`. Целостность проверяется командой `sha256sum -c templates/SHA256SUMS`.

> Болванка содержит проприетарную прошивку HP/QLogic. Она предоставляется только для восстановления собственного оборудования.

### Как сделать свою болванку

Превратите дамп рабочей карты в болванку без её данных:

```
python3 tools/nvmtool.py sanitize working_dump.bin -o template.bin
# MAC -> 02:4e:56:4d:00:00, SN -> XXXXXXXXXX, код даты -> 0000
```

## 6. Сборка образа для своей карты

Сначала обязательно прочитайте и сохраните исходное содержимое своего чипа (разделы 3–4) и проанализируйте его:

```
python3 tools/nvmtool.py info my_card_original.bin
```

`info` проверяет сигнатуру, все конфигурационные блоки с CRC, основную и расширенную директории и каждый образ. Выводит VPD, PCI ID и MAC-адреса, а если bootcode и модули MCP из разных релизов, выдаёт предупреждение.

Сборка образа с данными своей карты:

```
# MAC, серийный номер и код даты берутся из дампа самой карты
python3 tools/nvmtool.py build template.bin --from-dump my_card_original.bin -o my_card_new.bin

# или задаются явно (например, с наклейки на карте)
python3 tools/nvmtool.py build template.bin --mac aa:bb:cc:dd:ee:00 --serial CN0000ABCD --date-code 1234 -o my_card_new.bin
```

Что делает `build`:

- заменяет 8 подряд идущих MAC-адресов (2 порта × 4 функции Flex-10) везде, где они встречаются: manuf_info обоих портов и таблица multi-function (записи Ethernet, iSCSI и FCoE);
- записывает в VPD карты серийный номер (SN), MAC (V4) и, если задан, код даты (V2), пересчитывает контрольную сумму VPD (RV);
- пересчитывает CRC всех изменённых блоков и перед записью проверяет весь образ.

`--mac` — базовый MAC: порт 0, функция 0, наименьший из восьми (поле VPD V4). Серийный номер должен быть той же длины, что в болванке (у HP — 10 символов).

Версии прошивки и конфигурация берутся из болванки. Поэтому поля версий V1/V3/V6 в VPD описывают прошивку болванки, так и должно быть.

## 7. Полная процедура восстановления

1. Дважды снять копию флешки и сравнить: из Linux через `bnx2x_nvm.py read` (раздел 3) или программатором после выпаивания (раздел 4).
2. `nvmtool.py info backup.bin` и `bnx2x_nvm.py trace` — убедиться в диагнозе.
3. Взять готовую болванку или сделать свою с рабочей карты (`sanitize`), затем `nvmtool.py build ... --from-dump backup.bin`.
4. Записать образ: `bnx2x_nvm.py write` из ОС или через ESP + flashrom. Прочитать обратно и сверить SHA-256.
5. Если чип выпаивали, впаять его обратно (пин 1 — точка, по маркировке на плате).
6. Обесточить сервер на 30–60 с, затем включить.
7. В `dmesg | grep -iE 'bnx2x|MCP'` не должно быть `BAD MCP validity signature`, оба порта должны появиться с вашими MAC-адресами.

Обновлять прошивку в дальнейшем только средствами HPE на поддерживаемой ОС, не через `ethtool -f`, и перед каждым обновлением снимать дамп.

## Отказ от ответственности

Всё на ваш страх и риск. Неверный образ, напряжение или подключение могут необратимо повредить флешку или карту. Храните исходный дамп своего чипа.

HP, HPE, FlexFabric, Broadcom и QLogic — товарные знаки соответствующих владельцев. Проект с ними не связан.
