# Відновлення NVRAM HP 534FLR-SFP+ (BCM57810)

[English](../README.md) · [Polski](README.pl.md) · **Українська** · [Русский](README.ru.md)

Інструменти та інструкції для відновлення мережевих карт HP FlexFabric 10Gb 2-port **534FLR-SFP+** (Broadcom/QLogic **BCM57810**, `14e4:168e`, subsystem `103c:1930`), у яких на SPI-флеші опинився неузгоджений набір прошивки. Метод підходить і для інших карт на BCM57810/bnx2x з такою самою структурою NVRAM.

Склад репозиторію:

| Шлях | Вміст |
|---|---|
| `firmware/esp-serprog/` | Прошивка, що перетворює **ESP32 / ESP8266** на SPI-програматор для [flashrom](https://flashrom.org) (протокол `serprog`) |
| `tools/nvmtool.py` | Утиліта для образів: аналіз дампу, заготовка без даних карти, збирання образу для конкретної карти (Python 3, без залежностей) |
| `templates/` | Знеособлена заготовка для 534FLR-SFP+ (прошивка 7.14.62, без даних карти) |

> Заготовка в `templates/` не містить даних карти (MAC, серійний номер). Початкові дампи реальних карт тут не зберігаються: кожен містить серійний номер і MAC-адреси конкретної карти. Див. [Де взяти заготовку](#4-де-взяти-заготовку).

---

## 1. Симптоми

Карта не видна в iLO та ОС, у `dmesg`:

```
bnx2x: [bnx2x_init_shmem:...]BAD MCP validity signature
bnx2x 0000:05:00.0: part number 394D4342-31383735-31543030-47303030
bnx2x: [bnx2x_get_igu_cam_info:...]CAM configuration error
bnx2x 0000:05:00.0: probe with driver bnx2x failed with error -22
pci 0000:05:00.0: VPD access failed.  This is likely a firmware bug on this device.
```

Керуючий процесор (MCP) у BCM57810 запускає bootcode з флешки, але не завершує ініціалізацію. У випадку, з якого почався цей проєкт, CRC усіх образів на флеші були правильними, але **bootcode мав версію 7.16.15, а всі модулі MCP — 7.13.75** (часткове оновлення). `nvmtool.py info` розпізнає таку ситуацію. Рішення — записати повний узгоджений набір прошивки з робочої карти, зберігши MAC-адреси та серійний номер своєї карти.

Перепрошити карту на місці неможливо (драйвер не піднімається), тому флешку знімають і програмують програматором.

## 2. Флешка M45PE16

- Маркування: **4SPE16**, ST/Micron **M45PE16**, 16 Мбіт (2 МБ), корпус SO8W (208 mil), 2,7–3,6 В.
- JEDEC ID: `0x20 0x40 0x15`.

⚠️ **Розпіновка M45PE16 — НЕ стандартна для 25-ї серії.** Стандартні SOIC8-перехідники, кліпси та панелі для цього чипа під'єднані неправильно:

```
          ┌───────┐
    D   1 │●      │ 8  Q       D  = вхід даних (MOSI)    Q   = вихід даних (MISO)
    C   2 │       │ 7  VSS     C  = тактовий (SCK)       VSS = земля
 Reset  3 │       │ 6  VCC     S  = вибір чипа (CS#)     VCC = 3,3 В
    S   4 │       │ 5  W       W  = захист запису        Reset = скидання, активний 0
          └───────┘
```

Reset (пін 3) **обов'язково** підтягнути до 3,3 В, інакше чип залишиться у скиданні й читатиметься як `0xFF`/`0x00`.

Крім того, у сімейства M45PE **немає команди повного стирання** (Bulk/Chip Erase), є лише Page Erase `0xDB` і Sector Erase `0xD8`. Від цього залежить вибір програматора.

## 3. Програматори

### 3.1 TL866II+ (minipro): лише читання

TL866II+ чип **читає**, але **записати не може**. Його прошивка стирає SPI-флешки лише командою Bulk Erase (`0xC7`), яку M45PE16 ігнорує. minipro все одно пише `Erasing... OK`, потім записує дані поверх нестертих, і перевірка не проходить. У чипі лишається `старе AND нове`. Профіль `M45PE16` у базі minipro задано лише для T48/T56. Алгоритму для TL866II+ немає, і оновлення прошивки програматора його не додає.

Для читання на TL866II+ ніжки чипа з'єднують із тими контактами ZIF, які займала б стандартна SOIC8-флешка 25-ї серії (верх панелі, з боку важеля):

| Пін M45PE16 | Сигнал | Контакт ZIF | (позиція стандартної флешки) |
|---|---|---|---|
| 4 | S | 1 | CS |
| 8 | Q | 2 | DO |
| 5 | W | 3 | WP |
| 7 | VSS | 4 | GND |
| 1 | D | 37 | DI |
| 2 | C | 38 | CLK |
| 3 | Reset | 39 | HOLD (у «1») |
| 6 | VCC | 40 | VCC (3,3 В) |

```
minipro -p "M45PE16@SOIC8" -D            # очікується: Chip ID: 0x204015  OK
minipro -p "M45PE16@SOIC8" -r dump.bin
```

### 3.2 ESP32 / ESP8266 + flashrom: читання і запис ✅

flashrom підтримує M45PE16 (включно з посекторним стиранням) і працює з ESP через USB-UART за протоколом `serprog`.

#### Збирання та прошивання ESP

Потрібен [PlatformIO](https://platformio.org):

```
cd firmware/esp-serprog
pio run -e esp32   -t upload --upload-port /dev/ttyUSB0     # ESP32 DevKit
pio run -e esp8266 -t upload --upload-port /dev/ttyUSB0     # NodeMCU / Wemos D1 mini
```

Перевірка, що flashrom бачить програматор (флешку поки не під'єднувати):

```
flashrom -p serprog:dev=/dev/ttyUSB0:921600
# serprog: Programmer name is "esp-serprog"
```

Попередження `Warning: NAK to query serial buffer size` — очікуване й нешкідливе.

#### Під'єднання (безпосередньо до ніжок чипа)

| Пін M45PE16 | Сигнал | ESP32 | ESP8266 (NodeMCU) |
|---|---|---|---|
| 1 | D (MOSI) | GPIO23 | D7 (GPIO13) |
| 2 | C (SCK) | GPIO18 | D5 (GPIO14) |
| 3 | Reset | **3V3** | **3V3** |
| 4 | S (CS) | GPIO5 | D1 (GPIO5) |
| 5 | W | **3V3** | **3V3** |
| 6 | VCC | **3V3** | **3V3** |
| 7 | VSS | GND | GND |
| 8 | Q (MISO) | GPIO19 | D6 (GPIO12) |

- Живлення **лише від 3V3**, ніколи від 5V/VIN.
- Дроти короткі (≤ 10–15 см). Частота SPI за замовчуванням 4 МГц (максимум 8 МГц).
- Під'єднуйте дроти при від'єднаному USB.
- Варіант для ESP32 перевірено на реальному залізі з M45PE16. Варіант для ESP8266 збирається, але на залізі не перевірявся.

#### Читання і запис

```
P="serprog:dev=/dev/ttyUSB0:921600"

flashrom -p $P -c M45PE16                       # пошук: Found ... "M45PE16"
flashrom -p $P -c M45PE16 -r backup1.bin        # читання (≈30 с)
flashrom -p $P -c M45PE16 -r backup2.bin
cmp backup1.bin backup2.bin && echo "читання стабільне"

flashrom -p $P -c M45PE16 -w new.bin            # стирання + запис + перевірка (≈3 хв)
flashrom -p $P -c M45PE16 -r check.bin
sha256sum new.bin check.bin                     # мають збігатися
```

Якщо під час пошуку приходить `id1 0xff` (MISO підтягнутий, чип мовчить), перевірте живлення і Reset на пінах 6 і 3, а також проводку. Якщо й TL866 читає `0xff`, майже завжди винне неправильне під'єднання.

## 4. Де взяти заготовку

Потрібен повний дамп NVRAM на 2 МБ з **робочої** карти тієї самої моделі (той самий PCI subsystem ID: `103c:1930` для 534FLR-SFP+). З робочої карти в Linux-сервері:

```
ethtool -e <iface> raw on > working_dump.bin      # 2097152 байти
```

Або прочитайте її флешку програматором, як описано вище.

### Готова заготовка

У репозиторії є готова заготовка `templates/534FLR-SFP+_fw7.14.62_template.bin`. Це знеособлений дамп робочої 534FLR-SFP+ (`103c:1930`): bootcode 7.14.62 з повним узгодженим набором модулів MCP (7.14.62/7.14.37), MBA 7.14.10. Усі контрольні суми правильні. Дані карти замінено заглушками: MAC `02:4e:56:4d:00:00`…`07`, SN `XXXXXXXXXX`, код дати `0000`. Цілісність перевіряється командою `sha256sum -c templates/SHA256SUMS`.

> Заготовка містить пропрієтарну прошивку HP/QLogic. Вона надається лише для відновлення власного обладнання.

### Як зробити власну заготовку

Перетворіть дамп робочої карти на заготовку без її даних:

```
python3 tools/nvmtool.py sanitize working_dump.bin -o template.bin
# MAC -> 02:4e:56:4d:00:00, SN -> XXXXXXXXXX, код дати -> 0000
```

## 5. Збирання образу для своєї карти

Спочатку обов'язково прочитайте й збережіть початковий вміст свого чипа (розділ 3) і проаналізуйте його:

```
python3 tools/nvmtool.py info my_card_original.bin
```

`info` перевіряє сигнатуру, усі конфігураційні блоки з CRC, основну та розширену директорії й кожен образ. Виводить VPD, PCI ID і MAC-адреси, а якщо bootcode і модулі MCP з різних релізів, видає попередження.

Збирання образу з даними своєї карти:

```
# MAC, серійний номер і код дати беруться з дампу самої карти
python3 tools/nvmtool.py build template.bin --from-dump my_card_original.bin -o my_card_new.bin

# або задаються явно (наприклад, з наліпки на карті)
python3 tools/nvmtool.py build template.bin --mac aa:bb:cc:dd:ee:00 --serial CN0000ABCD --date-code 1234 -o my_card_new.bin
```

Що робить `build`:

- замінює 8 послідовних MAC-адрес (2 порти × 4 функції Flex-10) скрізь, де вони трапляються: manuf_info обох портів і таблиця multi-function (записи Ethernet, iSCSI та FCoE);
- записує у VPD карти серійний номер (SN), MAC (V4) і, якщо задано, код дати (V2), перераховує контрольну суму VPD (RV);
- перераховує CRC усіх змінених блоків і перед записом перевіряє весь образ.

`--mac` — базова MAC-адреса: порт 0, функція 0, найменша з восьми (поле VPD V4). Серійний номер має бути тієї самої довжини, що й у заготовці (у HP — 10 символів).

Версії прошивки та конфігурація беруться із заготовки. Тому поля версій V1/V3/V6 у VPD описують прошивку заготовки, так і має бути.

## 6. Повна процедура відновлення

1. Випаяти M45PE16 з карти (або використати кліпсу, пам'ятаючи про нестандартну розпіновку).
2. Прочитати двічі й порівняти (`cmp`). Зберегти початковий дамп.
3. `nvmtool.py info original.bin` — переконатися в діагнозі.
4. Зробити заготовку з робочої карти (`sanitize`), потім `build ... --from-dump original.bin`.
5. Записати через ESP + flashrom, прочитати назад і звірити SHA-256.
6. Впаяти чип назад (пін 1 — крапка, за маркуванням на платі).
7. Завантажитися: у `dmesg | grep -iE 'bnx2x|MCP'` не має бути `BAD MCP validity signature`, обидва порти мають з'явитися з вашими MAC-адресами.

Надалі оновлювати прошивку лише засобами HPE (SPP / Smart Component), не через `ethtool -f`, і перед кожним оновленням знімати дамп.

## Відмова від відповідальності

Усе на ваш страх і ризик. Неправильний образ, напруга чи під'єднання можуть незворотно пошкодити флешку або карту. Зберігайте початковий дамп свого чипа.

HP, HPE, FlexFabric, Broadcom і QLogic — торговельні марки відповідних власників. Проєкт із ними не пов'язаний.
